# Juri4 — бизнес‑процесс (как пользоваться)

## Кто пользуется

- **Юрист**: создаёт дела, загружает документы, вводит разногласия, отправляет дело на анализ и смотрит результат.

## 1) Логин

1. Откройте `https://abc.tail47eed8.ts.net` (или локально `http://localhost:3080`).
2. Войдите под учёткой (seed):
   - `lawyer@company.local` / `lawyer12345`

> Примечание: админки/регистрации нет — пользователей сейчас создаём через seed/БД.

## 2) Создание дела

1. Перейдите `Дела` → `Создать дело`.
2. Заполните минимум:
   - Название
   - Контрагент
   - (опционально) Тип договора / Описание / Заметки
3. После создания откроется карточка дела с вкладками.

## 3) Документы по делу

В карточке дела вкладка `Documents`:

1. Загрузите **основной договор** (категория `main_contract`).
2. При необходимости загрузите приложения/доп.файлы (`appendix`, `other`).
3. Если разногласия будут отдельным файлом — загрузите его как `disagreement_document`.

## 4) Разногласия

В карточке дела вкладка `Disagreements` выберите способ ввода:

- **Document**: загрузите файл протокола разногласий (фактически это загрузка файла с категорией `disagreement_document`).
- **Free text**: вставьте текст пожеланий/замечаний клиента (сохраняется при уходе из поля).
- **Manual items**: вручную добавьте пункты (номер/название, версии сторон, запрос клиента, комментарии).

## 5) База знаний (опционально)

Раздел `База знаний`:

- Добавляйте внутренние документы организации (политики, шаблоны, регламенты).
- При добавлении указывайте **Правила** — это текстовые инструкции, которые внешняя система анализа должна учитывать для этого документа/шаблона.
- Они будут доступны внешней системе анализа в контексте дела (попадают в ответ `GET /api/integration/cases/{id}/context`).

## 6) Анализ (через внешнюю систему по API)

1. На платформе подключите Tool **Custom HTTP API** к `juri4` (инструкция: `docs/platform-custom-api-juri4.md`).
2. В `juri4` откройте нужное дело и возьмите его `caseId` (UUID из URL вида `/app/cases/<caseId>`).
3. Во внешней системе обработчик должен:
   - вызвать `get_case_context` (получить контекст),
   - сформировать структурированный результат,
   - вызвать `submit_analysis_result`.
4. После `submit_analysis_result` в `juri4` появится `Analysis run`, а статус дела станет `completed`.

## 7) Просмотр результата

В карточке дела вкладка `Analysis`:

- выберите нужный запуск анализа;
- смотрите:
  - Summary
  - Final recommendation
  - Draft protocol text
  - Positions (пункты разногласий, риск, основания).

## 8) Как “очистить демоданные”

Если случайно посеяли demo‑кейсы и документы, проще всего сбросить БД и загрузки и посеять только аккаунт:

```bash
cd C:\1trim\urist\juri4
docker compose down -v
docker compose up --build -d
docker compose exec backend npm run seed
```

По умолчанию `seed` создаёт только организацию + одного юриста (без демо‑дел и документов).
